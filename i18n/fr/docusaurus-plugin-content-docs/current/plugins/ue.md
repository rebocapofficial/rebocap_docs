<p class="ue-doc-h" role="heading" aria-level="3">1. Importer le plugin dans le projet UE</p>

</div>
<div style="flex: 1.5; min-width: 250px;">

</div>
</div>

<div style="display: flex; flex-direction: row; gap: 20px; flex-wrap: wrap; align-items: center; margin: 15px 0;">

</div>
<div style="flex: 1.5; min-width: 250px;">

Faites glisser la variable dans le graphe et compilez une fois ; dans `Default Value` à droite, cliquez sur `+` pour créer un asset Map Data.

</div>
</div>

<div style="display: flex; flex-direction: row; gap: 20px; flex-wrap: wrap; align-items: center; margin: 15px 0;">
<div style="flex: 1; min-width: 250px; text-align: center;">

![La fenêtre de mapping des os de Rebocap](/img/ue_plugin/guide/06_bone_mapping.png)

</div>
<div style="flex: 1.5; min-width: 250px;">

Dans la fenêtre de mapping, renseignez une à une les noms d'os correspondants du personnage. `Select Bone Preset` remplit d'un clic la nomenclature par défaut d'UE ; si le squelette du personnage utilise d'autres noms, ouvrez la fenêtre du Skeleton et recopiez-les.

</div>
</div>

</div>

<p style="margin: 6px 0 0; font-size: 13px; color: var(--ifm-color-emphasis-600);">Figure 1 : comment les données de capture atteignent le personnage.</p>

<div class="ue-doc-sec">

<p class="ue-doc-h" role="heading" aria-level="3" id="rebocap-body-pose">Rebocap Body Pose</p>

<div style="display: flex; flex-direction: row; gap: 20px; flex-wrap: wrap; align-items: center; margin: 15px 0;">
<div style="flex: 1; min-width: 250px; text-align: center;">

![Nœud Rebocap Body Pose](/img/ue_plugin/nodes/body_pose_node.png)

</div>
<div style="flex: 1.5; min-width: 250px;">

Pilote en temps réel le squelette du personnage à partir des 24 nœuds de capture Rebocap. C'est le nœud principal du plugin : il lit le sujet LiveLink, convertit les transformations via l'asset de mapping des os et les écrit dans la pose.

Placez-le juste avant `Output Pose` et désignez un `Retarget Asset` : le personnage suit alors la capture.

</div>
</div>
<p style="margin: 6px 0 0; font-size: 13px; color: var(--ifm-color-emphasis-600);">Figure 2 : lorsque le flux arrive normalement, le titre affiche [60 Hz] et [Connected].</p>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Broches</p>

| Broche | Type | Défaut | Description |
| --- | --- | --- | --- |
| `Auto Submit Skeleton Data` | bool | true | À la première connexion, renvoie à Rebocap le squelette T-Pose du personnage (24 os + points de la plante des pieds) |
| `Connect Rebocap` | bool | true | Indique si le nœud se connecte automatiquement ; désactivé, la connexion ne se fait que depuis le panneau ou un Blueprint |
| `Enable Frame Interpolation` | bool | false | Interpole entre les images de capture lorsque la fréquence de rendu dépasse celle de la capture, pour supprimer l'effet d'escalier |
| `Interpolation Speed` | float | 45 | Vitesse d'interpolation (1–120) : plus la valeur est élevée, plus le suivi est réactif |
| `Hold Pose On Dropout` | bool | true | En cas de perte de paquets, conserve la dernière pose valide au lieu de revenir brutalement en T-Pose |
| `Show Viewport Debug HUD` | bool | false | Affiche en haut à gauche la fréquence de capture, les FPS du viewport et l'état de la connexion |
| `Retarget Asset` | class | `RebocapMapData` | Asset de mapping des os utilisé pour recibler les 24 nœuds de capture |

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Panneau Détails</p>

| Paramètre | Défaut | Description |
| --- | --- | --- |
| `LiveLink Subject Name` | rebocap | Nom du sujet LiveLink ; permet de distinguer plusieurs appareils ou instances |
| `Dropout Timeout (s)` | 2.0 | Durée maximale de maintien de la dernière pose |
| `Stale Frame Timeout (s)` | 0.25 | Une image plus ancienne que cette valeur est considérée comme perdue ; évite un gel définitif après la déconnexion |
| `Resume Blend (s)` | 0.15 | Durée de transition au retour du flux |
| `Throttle Skeleton Registration` | false | Expérimental : enregistre le squelette au plus une fois toutes les 2 s |
| `Zero-Alloc Static Subject` | false | Expérimental : évite les allocations répétées du squelette statique |
| `Optimize Frame Evaluation` | false | Expérimental : met en cache le rôle LiveLink pour réduire la contention sur les verrous |
| `Show Controlled Bones` | true | Met en évidence dans l'aperçu les os pilotés |
| `Joint Color` / `Link Color` | cyan / magenta | Couleurs des articulations et des liaisons |
| `Joint Radius` / `Link Thickness` | 2.2 / 1.6 | Rayon des articulations et épaisseur des liaisons |

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Utilisation</p>

1. Dans un Animation Blueprint, faites un clic droit et recherchez `Rebocap Body Pose` ;
2. Branchez-le juste avant `Output Pose` ;
3. Créez ou choisissez un asset `RebocapMapData` et renseignez les 24 os ;
4. Compilez : seuls les avertissements attendus sur les os absents du squelette doivent apparaître ;
5. Lancez une session PIE : le panneau de contrôle doit afficher environ 60 Hz.

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Remarques</p>

- La pose par défaut doit être <strong>T-Pose</strong> ; pour un personnage en A-Pose, branchez `Rebocap A-Pose to T-Pose` juste avant ce nœud.
- Les sommets de la plante des pieds lus par `Auto Submit Skeleton Data` ne sont disponibles que dans l'éditeur : le contact au sol est un peu moins bon après empaquetage.
- Sans `Retarget Asset`, le préréglage intégré est utilisé ; il exige des noms d'os identiques.

</div>

</div>
<div class="ue-doc-sec">

<p class="ue-doc-h" role="heading" aria-level="3" id="rebocap-a-pose-to-t-pose">Rebocap A-Pose to T-Pose</p>

<div style="display: flex; flex-direction: row; gap: 20px; flex-wrap: wrap; align-items: center; margin: 15px 0;">
<div style="flex: 1; min-width: 250px; text-align: center;">

![Nœud Rebocap A-Pose to T-Pose](/img/ue_plugin/nodes/a2t_node.png)

</div>
<div style="flex: 1.5; min-width: 250px;">

Convertit une pose de base A-Pose en T-Pose pour que `Rebocap Body Pose` puisse la piloter correctement. Destiné aux personnages MetaHuman, VRoid, MMD, Mixamo et autres, dont la pose par défaut est en A-Pose.

</div>
</div>
<p style="margin: 6px 0 0; font-size: 13px; color: var(--ifm-color-emphasis-600);">Figure 3 : <code>Alpha</code> contrôle le poids de mélange de la conversion.</p>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Broches</p>

| Broche | Type | Défaut | Description |
| --- | --- | --- | --- |
| `Base Pose` | Pose | — | Pose de base issue du nœud précédent |
| `Retarget Asset Override (Pin)` | class | vide | Facultatif : remplace temporairement l'asset de mapping via la broche |
| `Alpha` | float | 1.0 | Poids de mélange : 0 laisse la pose intacte, 1 applique la conversion complète |

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Panneau Détails</p>

| Paramètre | Défaut | Description |
| --- | --- | --- |
| `Select Preset Template` | UE5 Manny/Quinn/MetaHuman | Remplit d'un clic les 20 décalages d'os ; propose aussi MMD (env. 40°), VRoid/VRM (env. 40°), Mixamo (env. 45°) et Custom |
| `Symmetrical Edit` | true | Modifie uniquement le côté gauche ; le côté droit est mis en miroir automatiquement |
| `Invert Roll / Pitch / Yaw` | false | Inverse un axe lors du miroir |
| `Retarget Asset` | vide | Partagé avec `Rebocap Body Pose` |
| `Use Retarget Asset Bones` | true | Reprend les noms d'os de l'asset à chaque rafraîchissement |
| `1. Left Arm` … `5. Root & Spine & Head` | 0° | Décalages de rotation locale des 20 os |

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Groupes des 20 os</p>

| Groupe | Os |
| --- | --- |
| 1. Left Arm | clavicule gauche, bras gauche, avant-bras gauche, poignet gauche |
| 2. Right Arm | clavicule droite, bras droit, avant-bras droit, poignet droit |
| 3. Left Leg | cuisse gauche, mollet gauche, cheville gauche |
| 4. Right Leg | cuisse droite, mollet droit, cheville droite |
| 5. Root & Spine & Head | bassin, vertèbres 1–3, cou, tête |

</div>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Remarques</p>

- Les décalages sont des <strong>angles de rotation locale</strong>, pas des angles absolus ; les préréglages ne sont que des valeurs de départ.
- Sélectionner le nœud met en évidence dans l'aperçu les os ajustés (vert et doré pour l'A2T).

</div>

</div>
<div class="ue-doc-sec">

<p class="ue-doc-h" role="heading" aria-level="3" id="rebocap-map-data">Rebocap Map Data</p>

<div style="display: flex; flex-direction: row; gap: 20px; flex-wrap: wrap; align-items: center; margin: 15px 0;">
<div style="flex: 1; min-width: 250px; text-align: center;">

![Asset Rebocap Map Data](/img/ue_plugin/nodes/map_data_asset.png)

</div>
<div style="flex: 1.5; min-width: 250px;">

Asset qui associe les 24 nœuds de capture aux noms d'os du personnage ; les deux nœuds le partagent. Création : clic droit dans le Content Browser → `Miscellaneous → Data Asset` → `RebocapMapData`.

</div>
</div>
<p style="margin: 6px 0 0; font-size: 13px; color: var(--ifm-color-emphasis-600);">Figure 4 : sélecteur de préréglage, import/export JSON et les 24 champs de mapping.</p>
<div class="ue-doc-subsec">

<p class="ue-doc-sub" role="heading" aria-level="4">Préréglages intégrés</p>

<p class="ue-doc-h" role="heading" aria-level="3" id="parameter-quick-reference">Paramètres et dépannage</p>

| Symptôme | Cause probable | Solution |
| --- | --- | --- |
| Le personnage ne bouge pas | `Retarget Asset` non défini, ou mapping vide | Créez un `RebocapMapData` et remplissez les 24 os |
| Avertissement « os introuvable » pour `spine_04` / `spine_05` | Le mannequin UE4 n'a que 3 os de colonne vertébrale | Passez au préréglage UE4 (`spine_01/02/03`) |
| Tremblements, effet d'escalier | Fréquence de rendu supérieure à celle de la capture | Activez `Enable Frame Interpolation` |
| Un flash à la déconnexion | L'ancienne version se reconnectait automatiquement | Passez à la V3 |
| Pose figée après la déconnexion | L'ancienne version renvoyait sans cesse la dernière image | Passez à la V3 (`Stale Frame Timeout`) |
| Saut au moment de la reprise | La première image est appliquée d'un coup | Augmentez `Resume Blend (s)` jusqu'à 0.15–0.3 |
| Un port personnalisé ne se connecte jamais | L'application de capture n'écoute pas sur ce port | Retour automatique à 7690 après environ 4,5 s |
| Les pieds flottent après empaquetage | Sommets de la plante des pieds indisponibles à l'exécution | Limitation connue |
