# T2级别本地化（俄/韩/法/西）英文括号标注智能判断规则说明

**最后修订时间：** 2026年8月14日
**主要目的：** 在T2级别小语种文档中，为特定技术名词补充英文原词括号。其核心诉求是“方便小语种用户在使用Rebocap**全英文版软件界面**时，能将文档内容与软件界面上的英文UI功能按钮进行直观对照”。基于此诉求，为了保证阅读体验和页面排版整洁，特制定以下五条智能判定规则：

---

## 规则一：防嵌套重叠保护（Token引擎机制）
**逻辑：** 针对词库中互相包含的词（如“Magnetic Field Calibration”包含“Calibration”），绝不允许出现 `Калибровка (Calibration) магнитного поля (Magnetic Field Calibration)` 这种双重嵌套的低级错误。
*   **执行方式：** 脚本内置了 Token 占位符引擎。优先匹配长词组（如磁场校准），匹配成功后会对整个区域进行“神圣保护”（替换为不可见的 Token）。当后续尝试匹配短词（如校准）时，由于长词组区域已被保护，因此绝对不会在内部二次添加括号。

## 规则二：段落上下文感知（语义级屏蔽）
**逻辑：** 像 `Calibration`（校准）这种极其泛用的名词，如果独立成词到处加括号会非常“乱”。尤其当该段落明明是在讲“陀螺仪校准”，文中的“开始校准”就没必要再强行加一个指向主界面通用 `(Calibration)` 按钮的括号。
*   **执行方式：** 脚本在逐行扫描时具有“记忆功能”。它会记住当前处于哪个大标题之下。如果当前大标题（Heading）包含“陀螺仪(Gyroscope)”或“磁场(Magnetic)”的当地语言关键字，那么在该段落正文中出现的所有单独的“校准”字眼，脚本将智能判定为“语境已明确”，从而**直接跳过**，绝不添加 `(Calibration)` 括号，确保阅读自然。

## 规则三：精准区分“软件UI按钮”与“实体硬件”（黑名单规则）
**逻辑：** 加括号的本质是帮助用户找软件UI。因此，对于实体硬件设备名词，无论在哪出现均**绝不添加**英文括号，因为硬件实体不存在“英文UI对照”的需求。
*   **硬件黑名单（绝不加括号）：** 
    Tracker(追踪器) / Sensor(传感器) / Receiver(接收器) / Charging Case(充电盒) / Strap(绑带) / Battery(电池) / Blister Tray(吸塑托盘) 等。

## 规则四：文档配置区域禁区（Frontmatter屏蔽规则）
**逻辑：** 文档的侧边栏目录（Sidebar）和网页头部元数据是由 Markdown 顶部的 Frontmatter（即 `---` 包裹的内容）决定的。如果在这些区域加入括号，会导致左侧导航栏杂乱无章、极度难看。
*   **执行方式：** 脚本处理文件时，如遇到首行以 `---` 开头，则开启屏蔽模式。在此区域内的任何命中词汇（哪怕是软件UI词汇），均**原样保留，绝对不追加英文括号**，以此保证左侧目录的极致清爽。

## 规则五：原生态语法后缀保护（底层语法规则）
**逻辑：** 俄语和韩语是高度黏着或屈折语，词根后经常带有表示语法成分的后缀（如俄语字母后缀 `а`, `ов`，韩语助词 `를`, `가` 等）。如果强行在词根和后缀之间插入括号，会严重破坏句子的通顺和可读性。
*   **执行方式：** 当脚本发现外语翻译词后面直接粘连着属于该语言字母表内的字符时（如 `트래커가` 紧跟了 `가`），将**直接放过该词**，完全不添加英文括号，以保证原本语法的绝对通顺连贯。

**附录：一键修复脚本 (`fix_terms_v11.js`)**
最新版本的 Node.js 修复脚本已完全内化上述五大智能规则，不仅能避免嵌套，还能读懂段落上下文。只需执行 `node fix_terms_v11.js` 即可实现全库智能清理与标注。
